# 双引鲸全站页面闭环复刻设计

## 1. 目标

以当前账号实际可见的双引鲸 Web 系统为唯一复刻标准，逐页访问现网、完整取证并进行 1:1 复刻，最终形成一套可运行、可交互、可持续修改的本地原型系统。

允许使用脱敏 Mock 数据替代真实后端，但不得因此删除或简化现网可见的页面、字段、按钮、样式、布局、状态和操作路径。现网当前实装是验收标准；知识库、旧截图、历史静态原型和既有设计规范只用于辅助定位，不得覆盖当次现网观察。

项目完成时应同时具备：

1. 纳入范围的完整页面原型及可演示交互。
2. 与页面实现同步形成的组件库、样式体系及设计与交互规范。
3. 页面、组件、动作、数据、设计 Token 和资源的 Registry。
4. 可由 Renderer、Visual Editor 和后续 Agent 共用的 Page Schema。
5. 脱敏 Mock 数据模型和本地交互结果。
6. 可追溯的现网证据、视觉基线、自动测试及差异记录。

## 2. 范围与总页面目录

总页面目录是复刻范围和完成状态的唯一权威。第一版按左侧一级菜单、二级菜单登记：

- 一级菜单代表业务模块。
- 二级菜单是主要复刻页面和进度统计单位。
- 由二级菜单进入或跳转出的详情、新建、编辑、导入、打印等独立页面，作为子页面挂在对应二级菜单下。
- 页签、筛选结果、弹窗、抽屉、确认框、空态、加载态、校验态等作为页面状态挂在对应页面下，不重复计为一级或二级菜单。
- 现网访问过程中发现的新菜单、子页面和状态必须及时补入目录，不能因初始目录未登记而遗漏。
- 知识库已有但当前账号不可见的菜单标记为“当前账号不可见”，保留记录但不计入本轮完成范围。

每个二级菜单至少登记：一级菜单、二级菜单、入口、路由、页面类型、当前账号可见性、子页面、页面状态、现网访问状态、证据状态、复刻状态、对照状态、测试状态、验收状态及差异情况。

只有本轮范围内所有二级菜单及其子页面、页面状态全部验收通过，且不存在未归属入口，总页面目录才可标记为完成；总页面目录完成即代表本轮系统复刻完成。

## 3. 强制复刻主流程

每个二级菜单页面必须独立完成以下闭环：

1. **访问现网。** 从左侧菜单实际进入页面，记录账号角色、采集日期、浏览器、缩放比例、视口、入口和路由。
2. **遍历状态。** 操作全部可安全访问的页签、查询、重置、分页、排序、筛选、列设置、勾选、批量操作、新建、查看、编辑、删除、更多操作、弹窗、抽屉、确认框、返回和跨页跳转。涉及真实数据变更时只观察到提交前，不向现网写入。
3. **建立证据。** 保存截图、页面文本、DOM 信息、视觉度量、进入与退出方式、字段控件、默认值、表列、按钮、数据变化和跳转结果，并关联到总页面目录中的具体页面状态。
4. **允许开工。** 页面达到“已访问、证据完整、允许复刻”后才能编码。未访问现网的页面不得凭知识库、旧截图、模板、静态原型或记忆制作。
5. **完成复刻。** 按证据使用 Schema、Registry、Renderer、组件和 Mock 实现完整页面与交互。
6. **同视口对照。** 在相同视口下与现网逐项比较页面结构、字段、视觉、交互和状态；差异必须修正或经廖送平确认后登记豁免。
7. **同步提炼。** 将本页验证出的公共能力同步更新到组件、样式、设计规范、Schema、Action、Mock、Registry、证据和测试基线；页面特有能力保留在页面域内。
8. **页面验收。** 页面达到“已取证、已复刻、差异已处理、测试通过”后才能标记完成并进入下一页。

模块内所有二级菜单完成后执行一次模块级回归；总目录完成后执行全站回归。

## 4. 产品资料样板与技术底座验收

“产品管理 / 产品资料”是第一个完整样板页。它必须重新按强制复刻主流程覆盖全部现网可见状态，不能以现有代码、历史截图或默认首屏作为完成依据。

产品资料完成后，使用真实复刻结果核验现有 React + TypeScript + Vite、Registry、Schema、Renderer、Mock Runtime、组件体系和测试方式是否达到预期：

- 页面能否由同一份 Schema 完整表达，而不是依赖页面专属硬编码 JSX。
- Registry 是否能统一登记页面、组件、动作、数据、设计和资源。
- Renderer 是否能准确实现现网结构、视觉、状态和交互，而不会因抽象能力不足迫使页面降级。
- Mock 是否能支撑查询、分页、页签、列设置和本地增删改等演示结果。
- 组件抽象是否来自已验证共性，并允许页面级变体，不会为了复用删减现网差异。
- 自动测试和视觉对照是否既能证明代码可运行，也能证明页面复刻准确。
- Visual Editor 和后续 Agent 是否能与运行页面共用同一份 Schema。

不满足上述条件的底座能力必须先调整，并重新通过产品资料回归。只有廖送平确认“产品资料样板及技术底座通过”后，才能批量推进后续页面。

## 5. 持续提炼的公共资产

页面复刻过程中持续维护以下资产，不在项目末尾集中补写：

1. **组件库：** 菜单、页签、查询区、工具栏、表格、分页、表单、弹窗、抽屉、确认框、上传、图片预览等。
2. **样式体系：** 颜色、字体、间距、尺寸、边框、圆角、阴影、层级、遮罩、滚动、固定区域及响应式规则。
3. **页面模式：** 列表页、详情页、新建编辑页、工作台、导入页和分步流程页等标准结构。
4. **交互规范：** 查询重置、分页、排序、筛选、勾选、批量操作、保存取消、删除确认及成功失败反馈。
5. **状态规范：** 默认、悬停、聚焦、选中、禁用、加载、空数据、校验失败、操作成功/失败、无权限和危险操作确认。
6. **Page Schema：** 页面结构、组件属性、数据绑定、条件显隐、状态和页面元数据。
7. **Action：** 查询、重置、跳转、开关弹层、本地增删改、批量操作和状态反馈。
8. **Mock 数据模型：** 字段结构、关联关系、筛选、分页、本地 CRUD 和脱敏演示数据。
9. **Registry：** 页面、组件、动作、数据、设计 Token 和资源的统一登记。
10. **证据库：** 截图、DOM、视觉度量、采集上下文及其与目录项、实现项的关联。
11. **测试基线：** 单元测试、Schema/Registry 校验、页面交互测试、流程回归和同视口视觉对照。
12. **差异与豁免：** 现网行为、复刻行为、差异原因、影响、处理结果和确认记录。
13. **业务术语与文案：** 现网实际出现的字段名、按钮文案、提示语和状态名称。

提炼遵循“真实页面先于公共抽象”：先从已取证页面确认共性，再形成或调整公共资产；页面特有内容不得为了复用而强行统一。最后一个页面验收完成时，上述资产也必须完成整理、去重、验证和文档化。

## 6. 阶段设计

### 阶段一：建立总页面目录

登录现网，按左侧一级、二级菜单建立目录骨架，记录当前账号可见性。目录在后续访问中持续补充子页面和页面状态。

### 阶段二：完成产品资料样板

重新访问产品资料全部可见状态，补齐证据，完成 1:1 复刻、自动测试、同视口对照和差异处理。

### 阶段三：验收并调整技术底座

用产品资料最终效果验证 Registry、Schema、Renderer、Mock、组件、测试和编辑能力；不足部分先调整并完成回归。

### 阶段四：后续页面逐页闭环

按照总页面目录逐页执行“访问取证 → 复刻 → 对照 → 提炼 → 验收”，每个模块完成后执行模块回归。

### 阶段五：全站完成验收

确认全部范围内页面及状态已验收、公共资产完整、所有差异已处理、模块和全站回归通过，并将总页面目录标记为完成。

## 7. 对现有成果的重新评估

此前计划虽然声明“以现网为准”，但没有把访问现网、遍历状态和建立证据设置为每个页面开工前的强制动作，已经产生以下问题：

- 产品资料曾在证据不足时提前编码。
- 部分结构来自旧截图、静态原型和推测，无法证明与当前现网一致。
- 默认首屏之外的综合查询、列设置、新建编辑等状态缺少完整证据。
- 组件和样式可能基于不完整页面过早抽象。
- 现有测试主要证明代码能够运行，不能独立证明复刻准确。
- 技术 Phase 与页面完成状态交叉，容易形成偏高的进度判断。

因此，现有成果按以下规则处理：

1. 原有“已完成页面”全部重新核验，不能因代码存在就视为复刻完成。
2. 未经本轮现网访问的实现统一降级为“历史参考 / 待取证”。
3. 产品资料现有代码保留，逐项追溯证据；无证据部分重新采集后决定保留、修改或重做。
4. 总页面目录新增“现网访问、证据完整、允许开工”门禁。
5. 阶段推进改为页面闭环驱动，不再用纯技术 Phase 代表页面完成度。
6. 测试拆分为“代码运行正确”和“复刻准确”两类，两类均通过才可验收。
7. 现有组件、样式和设计规范重新核对证据来源；未经现网验证的内容标记为候选。
8. 按新完成标准重新计算项目进度，不沿用历史完成比例。

## 8. 验收与完成定义

单页面完成必须同时满足：

- 已从现网实际访问并覆盖全部可见子页面和状态。
- 字段、视觉、交互和状态证据完整且可追溯。
- 本地页面及 Mock 交互可运行。
- 代码测试和复刻准确性检查均通过。
- 差异已经修正或获得明确豁免。
- 本页面产生的公共资产已经同步更新。

全站完成必须同时满足：

- 总页面目录中所有纳入范围的二级菜单、子页面和页面状态均已验收。
- 当前账号可访问但未登记的入口为零。
- 所有模块回归和全站回归通过。
- 组件、样式、设计规范、Schema、Action、Mock、Registry、证据、测试和差异资料完整一致。
- 最终验收得到廖送平确认。

## 9. 安全边界

- 双引鲸现网仅用于授权范围内的只读观察和取证。
- 密码、验证码、Token 等敏感信息不得写入文档、代码、Git、截图说明或日志。
- 不通过自动化或原型向现网新增、修改、删除真实业务数据。
- 需要观察写操作流程时只进行到提交前；无法安全观察的结果必须标记未知或登记豁免。
- Raw、知识库和历史资料中的业务内容默认不是现网当前事实，必须以当次观察或明确权威来源验证。
