# 双引鲸产品资料一比一复刻设计

## 目标与边界

目标页面仅为贸易端 `产品管理 / 产品资料`（`/tsProductInformation`）。本试点的“1:1”指：在已授权、只读观察范围内，页面字段、默认值、控件状态、可见层、触发路径与本地 Mock 的可观察结果均与当次现网证据一致。

不接入真实后端、不向现网提交、保存或删除数据；本地“新增、编辑、删除”只改变脱敏 Mock 状态。未观察到的业务规则必须标记为未知，不得伪造为现网事实。

## 证据采集

使用 Playwright 临时人工登录窗口，以只读方式采集：截图、页面文本、DOM 可见控件、路由和计算样式。每次采集只覆盖一个可复核状态，并记录日期、入口、截图路径、字段、默认值和待确认项。

本试点必须覆盖以下状态：

1. 默认“单个产品”列表首屏。
2. 草稿产品、组合产品、客户专属、全部页签。
3. 关键词、是否有图、是否停产、产品状态的单项和组合筛选。
4. 综合查询抽屉及其分组、字段、默认值、重置和确定。
5. 图搜、导入、更多操作、行更多、列设置。
6. 新建和编辑宽幅表单的全部左侧锚点、表单字段、必填与底栏动作。
7. 删除确认层、取消与确认后的可见状态。
8. 分页、页大小、跳页与勾选状态。

## 运行时设计

页面继续以 Registry → PageSchema → Renderer 为单一事实源。每个采集出的字段、表列、按钮、抽屉和弹窗均注册为组件或 Action；产品资料特有能力可以作为业务组件注册，但不得旁路 Schema 写死到单独 JSX 页面。

Mock 数据按页面页签、产品状态、图片/停产标记、搜索字段和表格列建模。每次 Action 通过受控 Schema 或 Mock 状态更新运行页面：查询更新可见行，页签切换数据集，新增/编辑更新本地记录，删除确认移除本地记录，列设置更新可见列。

## 验收矩阵

每个采集项必须同时满足：

| 维度 | 通过标准 |
|---|---|
| 视觉与结构 | 截图中的壳层、字段顺序、列顺序、尺寸/密度、默认选中态和可见按钮一致。 |
| 字段 | 字段名称、控件类型、占位符、默认值、必填标识、分组、可见性与现网一致。 |
| 交互 | 相同入口打开相同本地层；关闭、取消、重置、确定等操作产生与现网可观察结果一致的本地状态。 |
| 数据 | 查询、页签、分页、列显示和删除均可改变 Mock 数据或可见结果；结果可被自动化断言。 |
| 证据 | 每项均链接到当次只读采集记录；没有证据则列为未知或待确认。 |

## 测试与门禁

每新增一项功能先写失败测试，再实现。测试分为 Schema/Registry 单元测试、页面交互测试与本地 Playwright 回归。产品资料试点完成前，需完成从入口到查询、综合查询、新建、编辑、删除确认、图搜、导入、更多、列设置、分页的本地操作回放。

只有所有采集项具备证据、所有对应测试通过、视觉走查无未登记差异，并得到廖送平明确“产品资料试点确认，可扩展”后，才能复刻首页或其他模块。

## 非目标

本试点不做自由拖拽、组件排序、撤销重做、版本发布、审计日志、真实文件解析、真实打印、真实权限、真实后端写入或全站复刻。
