# 双引鲸复刻原型平台总实施计划

> **For agentic workers:** 本总计划只定义范围、阶段依赖、交付物与阶段门禁。执行前必须阅读对应阶段的细化计划，并用 `superpowers:executing-plans` 或 `superpowers:subagent-driven-development` 逐任务实施。

**Goal:** 建立独立运行的双引鲸贸易端高保真复刻平台，先完成首页与产品资料的真实 Mock 交互，再逐步提供可视化编辑、版本、验证与 Agent 修改页面能力。

**Architecture:** 系统以 Registry 和 Schema 为唯一结构事实源。React Renderer、未来的 Visual Editor 与 Agent 都只读取和修改同一份校验后的 Schema；原系统只作为只读观察证据，所有业务交互在脱敏 Mock Runtime 内运行。

**Scope baseline:** [架构勘察](../../双引鲸复刻原型平台/architecture.md)、[页面清单](../../双引鲸复刻原型平台/page-inventory.md)、[组件清单](../../双引鲸复刻原型平台/component-inventory.md)、[交互清单](../../双引鲸复刻原型平台/interaction-inventory.md)、[现网页面复刻提示词](../../../09-提示词/现网页面复刻.md)

## 总体约束

- 现网是只读观察源；不得发起写请求、保存真实数据或记录凭据。
- Schema 是页面、组件绑定、数据绑定与动作绑定的唯一事实源；不维护平行的编辑器数据或 JSX 页面树。
- Registry 必须覆盖 Page、Component、Action、Data、Design、Asset；修改公共组件前必须能查询影响页面。
- 每次保存 Schema 必须先校验；错误返回字段路径、原因和修复提示。
- 所有页面以脱敏 Mock 数据运行，支持与页面范围相符的查询、分页、状态与本地 CRUD 演示。
- 先完成阶段 1 的首页与产品资料并获得确认，才开始全量复刻。
- 每阶段的完成条件都是：代码、自动化测试、可运行预览、Schema 校验、Registry 查询和文档同时成立。

## 阶段路线

| 阶段 | 名称 | 目标 | 主要产物 | 开始条件 | 完成门禁 |
|---|---|---|---|---|---|
| 0 | 项目勘察 | 识别现有资产与缺口 | 架构、页面、组件、交互、设计清单 | 已完成 | 已记录运行时路线、页面范围、证据与未知 |
| 1 | 基础设施最小闭环 | 建立 Schema 驱动的可运行基础 | React 应用、Registry、Schema 校验、Renderer、Mock、基础测试 | 总计划确认 | 首页/产品资料可从 Registry 解析并通过单元与 E2E 冒烟测试 |
| 2 | 阶段 1 高保真复刻 | 完整复刻首页与产品资料的可演示路径 | AppShell、首页、产品资料、抽屉/弹窗、设计规范回写、Playwright 流程 | 阶段 1 通过 | 规定的验收路径可点通，阶段 2 外页面未实施 |
| 3 | 页面规模化与验证 | 按菜单模块持续扩展复刻并防回归 | 页面采集模板、页面注册、组件扩库、行为/视觉 E2E | 用户确认阶段 1 | 每个模块独立通过证据、Schema、交互与回归检查 |
| 4 | 编辑与版本 | 让非程序员安全修改同一份 Schema | 编辑器、Undo/Redo、草稿/预览/发布、版本比较/回滚 | 至少三个模块稳定复刻 | 编辑、预览、发布、回滚都不绕过 Schema |
| 5 | 治理与影响分析 | 控制跨页面修改风险 | Dependency Graph、Audit Log、变更影响报告 | 编辑器与版本稳定 | 可查询组件影响页面、变更来源和版本差异 |
| 6 | Agent 接入 | 让 Agent 受控地修改现有页面 | Registry 查询、Schema 变更提案、校验/预览/E2E 闸门 | 治理能力完成 | Agent 不能直接改页面源码，失败变更可追溯与回退 |
| 7 | Agent 生成页面 | 基于已有设计和组件创建新页面 | 相似页面检索、Schema 生成、数据/动作绑定、人工发布门禁 | Agent 修改成熟 | 新页面复用既有设计、组件和验证链路 |

## 阶段依赖图

```text
阶段 0 勘察
    ↓
阶段 1 Registry + Schema + Renderer + Mock
    ↓
阶段 2 首页 + 产品资料高保真复刻 ──→ 用户确认
    ↓
阶段 3 全量页面与自动化验证
    ↓
阶段 4 可视化编辑与版本
    ↓
阶段 5 依赖图与审计
    ↓
阶段 6 Agent 修改页面
    ↓
阶段 7 Agent 生成页面
```

## 每阶段通用工作流

1. 在现网只读观察页面、字段和交互，记录证据与未知。
2. 查询 Registry，确认能否复用现有页面、组件、Action 和数据源。
3. 先写失败测试，再扩展 Schema/Registry/组件与 Mock Runtime。
4. 保存前执行 Schema 校验；运行本地单元、构建和 E2E 测试。
5. 更新设计规范、页面/组件/交互清单与实施追踪；以中文最小提交。
6. 阶段门禁通过后，记录版本、验证命令和下一阶段唯一入口。

## 验收标准映射

| 最终能力 | 对应阶段 | 可验证结果 |
|---|---|---|
| 像普通后台一样操作 | 2、3 | 菜单、页签、查询、弹窗、抽屉、分页和行操作可运行 |
| 后续页面风格一致 | 2、3 | 所有页面使用 Design Registry 与公共组件，不复制壳层 |
| 不写代码改文字、列、按钮、弹窗 | 4 | 编辑器修改 Schema 后预览与发布生效 |
| 保存、预览、发布、回滚 | 4 | Draft 与 Published 隔离，版本可比较和恢复 |
| 知道公共组件影响范围 | 5 | 组件查询返回使用页面和版本影响 |
| Agent 改已有页面 | 6 | Agent 经 Registry、Schema 校验、预览和 E2E 后生成版本 |
| Agent 建新页面 | 7 | Agent 复用页面模板、组件、Token、数据和 Action 生成可验证 Schema |

## 阶段计划管理

- 阶段 1 细化计划已在[基础设施计划](2026-09-10-双引鲸复刻基础设施.md)；执行前需完成计划评审。
- 阶段 2 至 7 在前置阶段完成、证据与接口稳定后分别编写，避免虚构尚未发现的现网字段与实现接口。
- 每份细化计划必须列出准确的文件、接口、失败测试、验证命令、阶段门禁与独立提交点。
