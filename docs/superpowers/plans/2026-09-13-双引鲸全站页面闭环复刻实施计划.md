# 双引鲸全站页面闭环复刻 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 以当前账号实际可见的双引鲸 Web 系统为唯一标准，按总页面目录逐页访问、取证、1:1 复刻和验收，直至目录内全部页面完成并同步形成完整公共资产。

**Architecture:** 总页面目录是范围与完成状态的唯一权威；每个二级菜单页面执行“现网访问 → 证据建档 → 允许开工 → Schema/Registry 驱动复刻 → 同视口对照 → 资产提炼 → 验收”的闭环。先用产品资料验证现有技术底座，确认后再逐页扩展，Visual Editor、Agent 和运行页面始终共用同一份 Page Schema。

**Tech Stack:** React 19、TypeScript 7、Vite 8、Vitest 5、Testing Library、Playwright 1.62、Registry / Page Schema / Renderer、静态 Mock Runtime、Git。

**Spec:** `docs/superpowers/specs/2026-09-13-双引鲸全站页面闭环复刻设计.md`

## Global Constraints

- 现网当前实装是唯一复刻标准；知识库、旧截图、历史静态原型和既有规范只作辅助。
- 未完成“已访问、证据完整、允许复刻”门禁的页面禁止编码。
- 现网只读观察；涉及真实写操作只观察到提交前，不新增、修改或删除真实数据。
- 密码、验证码、Token 和真实业务敏感数据不得进入文档、代码、截图说明、日志或 Git。
- Mock 可以替代后端，但不得删除或简化现网可见页面、字段、按钮、状态和操作路径。
- 页面不能以硬编码 JSX 作为唯一事实源；运行页面、Visual Editor 和后续 Agent 共用 Page Schema。
- 测试分为“代码运行正确”和“复刻准确”两类，两类均通过才可验收。
- 每完成一项可独立还原的任务立即中文提交；不自动推送远程。
- 工作区现有无关改动不得纳入本计划提交。
