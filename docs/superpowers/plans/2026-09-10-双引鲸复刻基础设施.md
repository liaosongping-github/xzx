# 双引鲸复刻阶段 1：基础设施 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 完成总实施计划的阶段 1：建立可运行、可测试的 React 原型应用，并实现由 Registry、可校验 Schema 与 Renderer 组成的最小闭环。

**Architecture:** 在 `03-产品工作/现网页面复刻原型/应用/` 新建独立 Vite 应用。`registry/` 只负责可查询的定义，`schema/` 只负责页面实例和运行时校验，`renderer/` 只根据注册表解释 Schema；Mock 数据通过 Data Registry 读取。首页与产品资料仅作为闭环种子，不在本计划实现完整高保真页面。

**Tech Stack:** Node.js 24.18.1、npm 11.16.0、React 19、TypeScript、Vite 8、Vitest、Testing Library、Zod、Playwright。

**Spec:** [总实施计划](2026-09-10-双引鲸复刻原型平台总实施计划.md)、[架构勘察](../../双引鲸复刻原型平台/architecture.md)、[页面清单](../../双引鲸复刻原型平台/page-inventory.md)、[组件清单](../../双引鲸复刻原型平台/component-inventory.md)、[交互清单](../../双引鲸复刻原型平台/interaction-inventory.md)、[现网页面复刻提示词](../../../09-提示词/现网页面复刻.md)

## Global Constraints

- 运行时唯一事实源是 Schema；React 页面不得绕过 Schema 直接定义业务组件树。
- Page、Component、Action、Data、Design、Asset 都通过 Registry 查询；本期先实现前四类及 Design Token 的只读定义。
- 任何 Schema 在写入或加载前必须经 Zod 校验；错误信息须包含失败路径和原因。
- 所有业务数据是脱敏 Mock 数据；禁止调用现网写接口、提交真实表单或写入凭据。
- 现网未验证的交互只模拟 UI 行为，不能写成现网业务事实。
- Visual Editor、Undo/Redo、版本、发布、依赖图、审计和 Agent 改页不属于本计划。
- 每项生产代码先完成对应失败测试；每项独立成果使用中文提交，暂存时不包含 Raw 自动同步文件。

- [ ] **Step 3: 实现六类 Registry 的最小类型与读取 API**

```ts
export class RegistryStore {
  private readonly entries = new Map<RegistryKind, Map<string, RegistryEntry>>();
  register<T extends RegistryEntry>(kind: RegistryKind, entry: T): void { /* 按 kind/id 保存，重复 id 抛错 */ }
  get<T extends RegistryEntry>(kind: RegistryKind, id: string): T | undefined { /* 返回对应项 */ }
  list<T extends RegistryEntry>(kind: RegistryKind): readonly T[] { /* 返回稳定数组 */ }
}
```

每个注册项必须至少含 `id`、`name`、`version`、`metadata`；Page 项追加 `route`、`schemaId`，Component 项追加 `rendererKey`、`propsSchema`，Action 项追加 `type`、`paramsSchema`，Data 项追加 `query`。
