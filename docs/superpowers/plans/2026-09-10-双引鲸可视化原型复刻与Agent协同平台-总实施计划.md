# 双引鲸复刻：当前执行计划

> 本文只记录当前有效的范围、事实、门禁与下一步。历史阶段记录、被替代的策略和对应提交见[计划演变与决策记录](history/双引鲸复刻计划-演变与决策记录.md)。Git 历史保留每一个旧版本，不在本文重复维护。

## 当前结论

- **当前范围**：只复刻“产品管理 / 产品资料”（`/tsProductInformation`），并以该页验证 Registry、Schema、Renderer、Mock、组件和最小编辑器路线。
- **不得提前扩展**：产品资料试点未获廖送平明确“确认，可扩展”前，不制作首页或其他业务页面，不启动全网现网普查。
- **最终范围**：当前账号现网可见的完整贸易端；知识库中的 13 个一级模块、50 个叶子入口仅是未来范围索引，当前不构成产品资料试点的阻塞。
- **唯一事实源目标**：运行页面、最小编辑器和后续 Agent 都必须读写同一套已校验 Schema 与 Registry；不得维持第二套硬编码页面事实。

## 当前唯一执行顺序

1. 固定产品资料本轮采集上下文：账号角色、日期、浏览器、缩放比例、视口和路由。
2. 只读采集 `PI-ADV`、`PI-COLUMNS`、`PI-NEW`、`PI-EDIT`、`PI-DELETE`、`PI-IMAGE`、`PI-IMPORT`、`PI-MORE`、`PI-ROW-MORE`，并补齐页签、筛选、分页、空态和可安全观察的反馈状态。
3. 将每项证据同步到页面状态、字段控件、交互、视觉度量和证据索引；未知项明确标为未知，不以旧截图或字段字典补造。
4. 每获得一项可复核证据，先写失败测试，再通过同一份 Schema、Registry 和 Mock 实现对应交互；优先修正 `GAP-001`，避免继续扩大双渲染路径。
5. 固定同视口完成本地/现网对照；所有差异修正，或取得廖送平明确豁免并登记。
6. 通过产品资料试点门禁后，提交演示与证据给廖送平；只有明确确认后，才决定全网普查和下一页面顺序。

## 产品资料试点门禁

| 门禁 | 通过标准 |
|---|---|
| 证据 | 所有当前账号可见页签、查询、表格、抽屉、弹窗、菜单、行操作和可安全触发状态均有当次只读证据，并关联清单项。 |
| 复刻 | 页面结构、字段、控件、文案、交互、状态和视觉均按证据实现；静态 Mock 只替代后端数据及计算，不删入口或过程界面。 |
| 架构 | 产品资料由已校验 Schema 与 Registry 驱动；`GAP-001` 已修正或获明确豁免。 |
| 质量 | 单元/集成测试、本地关键路径 E2E、同视口视觉对照和人工走查通过；未覆盖项有证据说明。 |
| 差异 | 差异清单无未处理项，或每个豁免均有现网行为、替代行为、原因、影响和廖送平确认。 |
| 确认 | 廖送平明确“产品资料试点确认，可扩展”或等效结论。 |

## 稳定规则

### 现网与数据边界

- 现网只用于授权范围内的观察和取证；不得通过自动化或原型新增、修改、删除真实业务数据。
- 密码、验证码、Token、Cookie 和真实业务敏感数据不得进入文档、代码、Git 或日志。
- 现网当前实装是复刻验收标准；知识库、历史原型、旧截图和设计规范只用于定位，不能覆盖当次观察。

### 1:1 的完成定义

单页验收必须同时满足：信息架构、页面内容、视觉、交互和已取证状态与现网一致；有同视口对照、测试结果与差异记录；本地 Mock 仅替换后端依赖；无证据的行为明确为未知或经确认豁免。

### 后续扩展规则

- 产品资料试点所必需的证据、Schema、Mock、组件、Renderer 修正、测试和最小编辑器能力可以并行推进。
- 只有扩大页面范围、启动全网普查、开始首页或后续业务模块时，需要产品资料试点门禁和廖送平明确确认。
- 产品资料确认后，每个二级菜单依次执行：现网访问 → 状态/证据建档 → 允许复刻 → 失败测试 → 实现 → 测试与构建 → 同视口对照 → 公共资产更新 → 页面验收。

## 长期目标与候选技术

最终系统要实现完整现网复刻、脱敏 Mock 交互、可编辑 Schema、版本与回滚、自动化验证和受控 Agent 修改。Puck/Craft.js、dnd-kit、MSW、Storybook 是后续编辑器、Mock 和文档能力的**候选选型**，尚未纳入当前运行时；需在产品资料试点验证后再选择，不能被当作已落地依赖。
