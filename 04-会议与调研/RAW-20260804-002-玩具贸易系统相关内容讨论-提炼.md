# RAW-20260804-002 玩具贸易系统相关内容讨论提炼

## 资料摘要与适用范围

本资料是一次入职业务与系统交流的飞书妙记原始产物。当前本地 Raw 仅包含飞书生成的会议纪要摘要、录制时间与时长，以及 1 条待办；不包含逐字稿、发言人姓名映射、参会人清单或现场材料附件。内容覆盖入职与培训复盘、玩具贸易获单和履约流程、双引鲸与小竹熊的候选边界、系统版本与配套服务、目标客户、价格与资质数据、财税合规风险、AI 方向及内部协作工具。

本文适合用于建立学习假设、规划系统实操和设计访谈问题；不适合作为正式产品规则、价格政策、组织制度、合规要求、销售口径或研发承诺的依据。

> Raw 多处将系统写作“双引擎”。工作空间已有独立确认：正式名称为“双引鲸”。本文统一使用“双引鲸”，但不修改 Raw 原文。

## 已验证事实

暂无。

原因：当前 Raw 是飞书 AI 生成的会议纪要摘要，没有可核验的逐字稿、发言人身份、授权范围、现场流程图或正式产品资料；其中的会议口径不能单独升级为已验证事实。

## 观点

以下均为“飞书 AI 会议纪要所概括的会议观点”，原始提出人和确认权限未知。

| 主题 | 会议纪要中的观点或主张 | 证据边界 |
|---|---|---|
| 入职与培训复盘 | 纸质录用函与此前电子版一致，薪资信息需保密；前期培训覆盖玩具产业、公司背景和小竹熊操作，双引鲸仅做基础介绍 | 未附录用函、制度原文、培训材料或发言人信息，需分别向人事和培训负责人核对 |
| 贸易主流程 | 销售可从销售报价、展厅择样、小竹熊报价和独立站订单进入；有库存时可跳过采购，无库存时需向工厂采购备货 | AI 摘要对流程做了压缩，未提供正式流程图、单据和状态证据 |
| 仓库与结算 | 工厂直送货场装柜时仓库环节可选；货物离港换单后生成应收/应付，挂账场景的单据处理与仓库模块有关；流程图实线/虚线分别表示必走/可选节点 | “离岸节点”“暂存仓库”等表述的业务含义不清，不能据此确定系统触发规则 |
| 系统定位 | 小竹熊被描述为工厂展示推广与贸易公司找样的平台；双引鲸被描述为贸易公司的销售、采购、跟单、仓库和财务全链路管理系统 | 缺正式产品说明、模块矩阵和客户验证 |
| 系统连接 | 双引鲸内嵌小竹熊入口用于跳转选品比价，后续拟实现产品信息一键同步至双引鲸产品库 | AI 摘要没有区分已上线能力与路线设想，实际集成状态未知 |
| 目标客户 | 双引鲸主要服务有一定体量、需要标准化流程的玩具贸易批发商，不以零散二道贩子和小店主为主要目标 | 客户分层标准、样本和排除规则未提供 |
| 价格数据 | 小竹熊公开价由工厂设定，平台不介入线下议价；采购底价被视为敏感信息，系统不应强制记录或暴露 | “系统”具体指小竹熊、双引鲸还是两者均未说明，且与实际页面价格字段需进一步核对 |
| 资质与纠纷 | 工厂上传产品证书，贸易公司查询资质，平台参与认证和专利侵权纠纷协调 | 能力归属、审核主体、责任边界和留痕规则均未说明 |
| 版本体系 | 基础版、专业版、展厅版按流程能力和存储容量分层；扩容定价仍在调整，三个版本处于预售测试并有行业客户参与打磨 | 正式名称、容量、客户数量、发布阶段和商业化口径均未核验 |
| 配套服务 | 扫码枪、热敏打印机、打印纸等由第三方供应，系统方收取服务费并提供远程及线下支持 | 供应模式、价格、服务范围和 SLA 未提供正式资料 |
| 产品方向 | 产品应贴合玩具贸易真实场景、收集营销一线反馈，并探索 AI 会议记录等提效能力 | 仅为方向性主张，未形成正式需求、负责人、优先级或验收标准 |
| 财税合规敏感场景 | 会议纪要提出系统要适配“非合规入账”等特殊业务需求 | 属高风险表述，不能据此推导产品应支持规避财税、审批或审计要求 |
| 内部工具与组织 | 公司产研、营销、综合管理使用不同协作工具，可评估统一办公工具；组织被概括为三个核心板块 | 未附正式组织架构、工具规范或管理制度 |

## 推测

| 推测 | 依据 | 可信度 |
|---|---|---|
| 销售、采购、跟单、查货、仓库/直发、换单和财务可能构成双引鲸端到端主干流程 | AI 纪要将这些节点放在同一贸易系统流程中，且与既有培训材料方向接近 | 中；尚无正式流程图和端到端实操证据 |
| “不强制记录采购底价”可能主要强调敏感数据保护，而不代表双引鲸完全没有价格字段 | 已浏览的双引鲸产品资料页面存在“出厂价”“进货价”等字段；当前 Raw 未区分参考价与实际成交价 | 中低 |
| 基础版、专业版、展厅版可能是同一产品的商业套餐分层 | AI 纪要同时使用版本、模块、容量、扩容和预售等商业化表达 | 中低 |
| 证书、认证和侵权协调更可能偏小竹熊平台侧能力 | 相关描述与工厂上传产品、贸易公司找样的上下文相邻 | 中低 |

## 候选业务/产品/系统知识

- 候选获单与履约主干：多入口选品/报价 → 销售订货 → 判断库存 → 按需采购 → 跟单/查货/送货 → 自有仓库入出库或工厂直送 → 换单 → 应收/应付及结算。
- 候选系统边界：小竹熊偏工厂展示、贸易公司找样和公开信息比价；双引鲸偏贸易公司内部销售、采购和履约管理。当前可能已有内嵌跳转，深度数据同步状态待验证。
- 候选版本分层：基础版、专业版、展厅版可能按做单、流程/审批深度、展厅能力和存储容量区分。
- 候选客户画像：有一定业务体量、需要规范销售采购与履约管理的玩具贸易批发商。
- 候选数据约束：需区分平台公开价、销售报价、产品参考价和订单实际采购价，并按角色、场景和导出范围保护敏感信息。
- 候选合规能力：产品证书上传、查询、认证及侵权纠纷协同；系统归属、审核责任和证据留痕仍未知。
- 合规红线候选：对“非合规入账”等高风险场景，不从 AI 纪要推导产品能力，必须先获得财务、法务/合规和有权产品负责人的正式边界。
