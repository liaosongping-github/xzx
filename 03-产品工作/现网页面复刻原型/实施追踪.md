# 双引鲸复刻原型平台实施追踪

> 本文件是长期实施的续接入口。任何 Agent 接手前，先读本文件、[现网页面复刻提示词](../../09-提示词/现网页面复刻.md)、[双引鲸设计规范](../设计规范/双引鲸/README.md)与[Agent 交接文档](../../06-长期记忆/agent切换交接文档.md)。

## 目标与边界

- 目标：建立独立运行、可交互的双引鲸贸易端复刻原型；先交付首页与产品资料，再经确认扩展。
- 架构方向：页面、组件、动作、Mock 数据、设计 Token 与资源均可注册；页面由 Schema 描述，并由 Renderer 渲染。
- 单一事实源：Visual Editor、Agent 和运行时未来必须共用同一套 Schema；禁止为任一入口另建页面数据。
- 数据边界：只使用脱敏 Mock 数据；现网仅作只读观察，不调用写接口，也不记录凭据。
- 当前实现形态：现有阶段 1 的高保真静态原型要求仍有效；Schema、Registry、Renderer 等平台能力须先经过项目勘察和实施计划拆分后再开发。

## 已确认的实施顺序

1. 项目勘察：仓库、现有原型、设计规范、可用技术栈、测试基线、现网访问方式与首页/产品资料的页面清单。
2. 最小基础设施：类型化 Registry、可校验 Page Schema、最小 Renderer 与 Mock 数据契约。
3. 公共壳与组件：先依据现网观察抽取全局壳、列表骨架、查询、表格、分页、抽屉、表单弹窗、确认框。
4. 阶段 1 复刻：首页与产品资料实现真实的本地交互；同步回写设计规范与公共组件说明。
5. 验证与停点：手工关键链路 + 自动化检查；由廖送平确认阶段 1 后，才开始全量页面。
6. 后续增量：Visual Editor、Undo/Redo、版本/发布、依赖图、审计、Playwright 对照验证、Agent 改页与生成页。

## 每次续接操作

1. 确认当前分支为 `codex/dyj-prototype-platform`，查看 `git status --short`；不接管未归属的 Raw 自动同步改动。
2. 阅读本文件的「当前状态」「本次工作记录」和「下一步唯一入口」；再按任务读取直接关联规范与代码。
3. 开始一项可验证的小任务前，在「本次工作记录」登记目标、涉及文件和验证命令；完成后补上结果、commit 与下一步。
4. 每一项可独立还原的改动单独以中文 commit，并默认 push；提交时仅暂存本项目明确列出的文件。
5. 中断前更新本文件、`工作台/今日.md` 和 `agent切换交接文档.md`；若本文件或工作台变动，运行 `node 08-自动化/build-workbench.mjs`。
