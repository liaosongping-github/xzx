# 协作偏好

## 已确认偏好

- 在开始设计或执行重要工作前，先尽可能厘清双方已知与未知的信息。
- 需求澄清本质上采用“廖送平知道/不知道 × Agent 知道/不知道”的认知矩阵。
- 工作空间以 Markdown 为知识底座，并支持 HTML 原型；**双引鲸相关原型默认高保真**，须遵循 [`03-产品工作/设计规范/双引鲸/`](../03-产品工作/设计规范/双引鲸/README.md)（现网优先，摹客仅交互参考；组件库 Element Plus + vxe-table v4）。全页须**引用** [`组件/`](../03-产品工作/设计规范/双引鲸/组件/README.md) 片段，禁止按印象重画壳层。非双引鲸演示需求可仍用低保真。
- **双引鲸弹窗原型跟手改稿（采购变更确认）**：用户手改后的截图是结构权威，不要用口头一句就砍列或改信息架构。对照表默认 **5 列**（序号、字段名、采购单当前值、销售单当前值、同意后销售单值更新为）；末列含表头浅蓝底；已拒绝末列划线；已同意划「销售单当前值」；「同意后」可以不等于采购当前值。卡片层级与边框：**销售卡外框**（灰边白底）+ **销售头灰底** `--dyj-bg-table-header`（`#f5f7fa`；销售订货单 + 客户名称 + 修改产品数，头加高）→ **内边距里嵌采购卡**（白底、灰边圆角）→ 采购头白底（采购订货单 + 厂商名称 + 修改人 + 修改时间 + 整单拒绝/整单同意）→ 产品头白底（缩略图 + 产品编码 + 客户货号 + 拒绝更新/同意更新；已同意右侧为「操作人：姓名 + 时间 + 已同意」绿字状态，已拒绝不显示操作人/时间）→ 表白底。一张销售单可含多张采购卡，采购卡之间留空隙。页签 `待确认 (N)` 为**销售单组数**，已处理不带条数；不要图例。**不要加底栏「关闭 / 确定」或其它底栏按钮**，关窗靠右上 ×；底栏只要现网分页（左：共 N 条 + 页大小 `100`；中：页码；右：前往）。标签全角冒号；表头短称按稿。提示条通栏浅蓝底（`--dyj-color-primary-light-9`），上下与标题栏、页签各间隔 `--dyj-dialog-body-padding`（20px）。对照表不要列表页斑马纹/行 hover/sticky 表头。产品编码/客户货号跟稿用灰字，不改蓝链。
- **知识库不落一次性产物**：`02-业务知识库/`（含字段字典）、`05-决策记录/`、`06-长期记忆/` 只维护 Markdown 权威文档；禁止写入 xlsx、csv、zip、临时脚本等一次性产物。用户消息里的知识库路径默认是**内容来源**，不是保存位置；未明确说「保存到该路径」时先问落盘目录。生成 Excel 等导出时落到用户指定路径，未指定则先问。Cursor Rule：[`知识库-禁止一次性产物.mdc`](../.cursor/rules/知识库-禁止一次性产物.mdc)。
- **提示词库**：可复用提示词放 [`09-提示词/`](../09-提示词/README.md)；聊天说「用提示词：口令」或 `@` 该文件。`08-自动化/` 内系统绑定提示词不搬，只在索引挂链。
- 文件夹、文件名、标题和正文优先使用中文。
- 稳定编号可以使用英文前缀，例如 `REQ`、`PRD`、`DEC`。
- Agent 可以分层自动沉淀工作事实与协作偏好，但不得保存账号凭据或无关隐私。
- **工作台分工**：人类日常入口为 [`工作台/我的工作台.html`](../工作台/我的工作台.html)；Agent 权威文本为 [`工作台/今日.md`](../工作台/今日.md)。根目录 `今日工作台.md` 仅为跳转说明。
- **待确认区**：草案统一放 [`00-待确认区/`](../00-待确认区/README.md)（工作日报 / 知识候选 / 协作偏好 / 决策）。廖送平在 HTML 点确认 → 复制口令 → 粘贴到 Cursor，由 Agent 写入正式路径；HTML 不直接改仓库。
- **Raw 知识落库须确认**：凡从 Raw 学习完成且有内容要写入 `02-业务知识库/`、`05-决策记录/` 或 `06-长期记忆/`（协作偏好 / 工作档案 / 待确认问题等）时，须先写入 `00-待确认区/知识候选/`（或对应子目录）供确认；确认前不得直写上述正式区。`04-会议与调研/` 提炼稿可在消化时直接写入。历史已落库条目不回溯。**第二阶段**再改消化提示词强制执行本条；当前骨架已就绪，新消化应尽量遵守。
- 未整理原始资料区命名为“原始文件（Raw）”。
- 首期遵循 MVP 原则，真实需要出现后再扩展复杂能力。
- **飞书资料入 Raw（默认仅索引）**：后续凡飞书**云文档**（docx / wiki 等）与**妙记**，**默认不把源文件同步回本地 Raw**；只在 [`01-原始文件（Raw）/README.md`](../01-原始文件（Raw）/README.md) 登记索引行（编号、摘要、学习状态、在线链接等）。权威内容以飞书在线为准。仅当廖送平**明确要求**拉本地副本时才下载/落盘。历史已落盘的本地 Raw 不回溯删除。样例：`RAW-20260808-004` / `005`。
- 线下沟通仍优先用飞书妙记留存；廖送平提供链接后由 Agent 按上条登记。若（例外）保存妙记/智能纪要到本地，必须直接保存原文，不得删减、改写或二次压缩；提炼另建下游文件。
- Raw 索引中的每条资料都必须填写“文档摘要”，用于在不加载源文件时初步判断资料相关性；摘要仅保存在索引中。有本地原文时不改动原文；仅在线链接条目则摘要写在索引行即可。
- Raw 索引固定维护“编号、入 Raw 时间、类型、主题、文档摘要、学习状态、知识库落点、最后学习时间、原始资料”；来源和载体保留在 Raw 元数据或原始资料链接中，不在索引重复维护。
- Raw 索引中的每条资料都必须填写“知识库落点”，链接该资料学习、提炼后在 `02-业务知识库/` 中形成或更新的条目；完整评估后没有可沉淀知识时明确写“无新增知识（已完成评估）”，不把提炼稿、任务或 Raw 原文当作知识库条目。
- Raw 主文档及其引用附件发生变化后，应自动转为“部分学习”并重新消化；成功后恢复“已学习”并更新最后学习时间，失败时保留上次知识库落点和学习时间。
- **工作日报（对内 / 对外）**分为两份；**对外内容是对内的子集**，生成时先定对外条目，再写入对内「对外同步」小节，最后补「仅对内」条目：
  - **固定顶层结构**（对内、对外相同）：仅「一、今日完成事项」「二、明日工作计划」；不设「今日收获」「当前待解决事项」。
  - **保存路径**（均在 `03-产品工作/工作日报/` 下）：
    - 对内：`对内/YYYY-MM-DD-工作日报.md`
    - 对外：`对外/YYYY-MM-DD-工作日报.md`
  - **对外日报**（提交公司）：
    - 正文为**单层编号列表**，不写小标题。
    - 仅写与公司业务、岗位职责直接相关的内容（如入职培训、产业认知、双引鲸 ERP 学习与实操、流程图/主链路梳理、与领导/同事沟通、疑问与优化整理、进度百分比等）。
    - **不得**出现 Agent、Raw、Codex/Cursor、协作偏好、自动化链路等内部协作细节；不得把「知识库/Raw 消化落盘」当作对外完成事项，除非当天确有可对外表述的业务产出。
    - **时长**：廖送平补充的完成事项若带时长，须在对外及对内「对外同步」对应条目中保留（统一写成「N 小时」，如 4 小时、1.5 小时）；不得只写在「仅对内」，也不得省略。
    - 口径参考 `对外/` 下 8/3—8/7 已归档样例（最新完整双轨样例见 8/7）。
  - **对内日报**（工作空间协作）：
    - 「一、今日完成事项」「二、明日工作计划」下各分 **`### 对外同步（业务工作）`** 与 **`### 仅对内（工作空间 / Agent 协作）`** 两节。
    - **对外同步**：与对外日报对应条目**逐条一致**（措辞可因补充微调，但语义不得冲突）；可在此节为同一业务事项补充 Agent 协作细节（如本地路径、工具验证），若细节不宜对外则只写在「仅对内」。
    - **仅对内**：Agent 协作、Raw 消化、自动化、协作偏好、工作空间维护等；可写编号、文件名、工具名。
    - 完整样例：[2026-08-07 对内工作日报](../03-产品工作/工作日报/对内/2026-08-07-工作日报.md)。
  - **定时生成**：每个上班日 18:00 由 Cursor 自动化根据当天工作记录**同时生成对内、对外两份草案**；上班日按 [大小周工作日规则](大小周工作日规则.md) 判定（大周周一至周六、小周周一至周五，周日休息）。
  - **确认后落盘**（自动化、手动补写均适用）：
    1. 生成草案后**先发廖送平确认，未确认前不落盘**。
    2. 廖送平可补充未经 Agent 处理的线下工作内容；Agent 未知部分**不得编造**。
    3. 若有补充：基于 Agent 可见记录**与**廖送平补充，**重新生成对内、对外两份**；再次发送确认。
    4. **最终确认后**方可写入对应文件夹；同一天重复生成时更新同一文件，不创建重复版本。
- 生成或更新工作日报等需归档的本地文稿时，草案优先放入 `00-待确认区/工作日报/`，确认后落盘；未确认前不写入 `03-产品工作/工作日报/`。
- **工作周报（单份 · 对外口径）**：
  - 结构：`一、本周完成的工作` → `二、下周工作计划` → `三、本周工作总结`。
  - 标题：`# M月D日—M月D日工作周报（第N周）`；第 N 周以当周周一所在自然月计算：`floor((日-1)/7)+1`。
  - 路径：`03-产品工作/工作周报/YYYY-MM-DD至YYYY-MM-DD-工作周报.md`；草案优先 `00-待确认区/工作周报/`。
  - 主素材为当周 `工作日报/对外/`；口径同对外日报；不写 Agent/Raw/自动化等内部细节。
  - Skill：`generate-weekly-work-report`；模板：`07-模板/工作周报-模板.md`。
  - **定时**：当周最后一个上班日 18:00（大周周六 / 小周周五）；cron 可为 `0 18 * * 1-6`，非末日在 Instructions 内跳过。提示词：`08-自动化/工作周报定时任务-提示词.md`。
  - 确认后落盘流程同日报（先确认、可补线下、再落盘）。
- **个人 Skill 跨 Agent 同步**（后续新增 skill 默认按此办理，与飞书 `lark-*` 同款）：
  1. **权威源（只维护一份正文）**：`%USERPROFILE%\.agents\skills\<skill-name>\`
  2. **Cursor**：在 `%USERPROFILE%\.cursor\skills\<skill-name>` 建 Windows **Junction**，指向上述权威源目录。
  3. **Codex**：优先依赖其读取 `.agents\skills`；若会话中发现不了该 skill，再在 `%USERPROFILE%\.codex\skills\<skill-name>` 建同样 Junction。
  4. **禁止**在 Cursor/Codex 目录再各写一份实体副本（历史 `generate-daily-work-report` 双副本除外，后续迁移时再改）。
  5. **禁止**把整个 `.cursor\skills` 或 `.codex\skills` 链到 `.agents\skills`（避免盖住各端自有 skill）；按 skill 目录逐个 Junction。
  6. 改规则时只改权威源；工作空间可另留提示词/模板副本（如 `08-自动化/*定时任务-提示词.md`），与 skill 正文同步维护。
- **需求入池**：飞书方案/PRD → 飞书「双引鲸需求管理」+ 本地需求池/REQ。走个人 Skill `requirement-pool-sync`（权威源 `~/.agents/skills/requirement-pool-sync/`）。先出映射表确认再写；默认不加描述/方案列；编号用调研日；知识库默认不写。
- Raw 是统一资料入口，不局限于飞书；人工粘贴或复制到 Raw 的常用文档、表格、演示文稿和图片也应自动进入知识消化流程。附件不独立触发，随引用它的主文档处理。
- 自动消化不得写入“已验证事实”；拟写入知识库/长期记忆的候选内容须经待确认区确认（见上「Raw 知识落库须确认」）。
- 与廖送平/任意 Agent 的聊天由本机自动化同步为 Raw（Cursor / Codex 可落盘会话自动抓取，其他来源可放入 `01-原始文件（Raw）/Agent聊天手动导入/`），再按信息分级分流到知识库与长期记忆。
- 跨 Agent 接手以工作空间 Markdown 为准；新 Agent 先读 [agent切换交接文档](agent切换交接文档.md)，不要求翻聊天原文。
- 实质性会话结束或切换 Agent 前，必须更新 agent 切换交接文档与 `工作台/今日.md` 中的阻塞/等待反馈。
- 聊天类 Raw 的自动消化可更新协作偏好、工作档案、待确认问题与候选知识（候选先进待确认区）；临时指令不得写入长期偏好；仅在廖送平明确确认“已验证/这是事实”时才可写入已验证事实。
- Raw 消化默认由「当前会话所在 Agent」执行（Cursor / Codex 聊天会话等）；本机 `raw-pipeline` 的 Codex CLI 自动消化为可选后备，默认关闭（`digest-engine.json` 中 `mode=session-agent`），避免 Codex API 断连时空转失败。采集桥：妙记默认**仅登记 README（不落本地源文件）**；agent-chat 仍同步聊天落盘；只停/旁路「调用 Codex 消化」。
- 廖送平说「待办 / todo / 记一下」且未指定平台时，**默认写入工作空间**：优先 `工作台/今日.md`（任务四象限或「待办」节），必要时同步 `agent切换交接文档.md` 的进行中事项。**仅当**明确说「飞书任务 / 任务中心 / 飞书待办」或给出任务/清单链接时，才走飞书任务（`lark-task`）。「妙记里的待办」走妙记待办能力，不与上述混淆。平台仍不明确且影响较大时，先问一句再执行。
- 可视化数据刷新：更新 `工作台/今日.md` 或 `00-待确认区/` 后，运行 `node 08-自动化/build-workbench.mjs` 再打开 HTML。
- **工作空间 Git**：
  1. 远程 `origin` 固定为 [liaosongping-github/xzx](https://github.com/liaosongping-github/xzx)；commit 后默认 `git push`（当场说不要推除外）。
  2. **自动 commit**：完成一件可独立还原的改动后立即提交，不必等廖送平再说「提交」。
  3. **最小颗粒度**：一次 commit 只含一件可单独还原的事；禁止把无关改动捆在一起。目的是以后能还原到指定节点。
  4. **说明用中文**：1–2 句，写清改了什么、为何改。
  5. 不入库：`08-自动化/.runtime/`（含登录凭据）、`node_modules`、日志；禁止提交密钥。
  6. 执行层：Cursor alwaysApply Rule [`.cursor/rules/git-自动细粒度提交.mdc`](../.cursor/rules/git-自动细粒度提交.mdc)；`AGENTS.md` 仅指针。
- **文风（对外/对内日报、周报及类似业务文稿）**：用自然、口语化但仍职业的中文；避免「AI 味」套话与空洞管理腔。典型禁用或慎用示例：「收口」「对齐」「闭环」「赋能」「抓手」「沉淀认知」「形成共识」「落地闭环」等；能直说就直说（如「继续完成遗留的单据状态梳理」优于「收口遗留梳理」）。
- **对用户聊天默认短答优先**（管对话，不管业务文档完整度）：
  1. **第一句就是结论**；禁止「先看了…再告诉你」等铺垫。
  2. 默认不超过约 8 条 bullet；用户没要时不给对照表、目录树、多方案。
  3. 细节不主动展开；口令 `简短` = 结论+下一步，`详细` = 展开。
  4. **范围**：REQ / PRD / 原型 / 日报 / 周报 / 知识库等正式产出仍按既有结构书写，不受短答压缩。
  5. **例外**：安全边界、信息分级、落盘确认、命令事前说明不得因短答省略。
  6. 执行层：Cursor alwaysApply Rule [`.cursor/rules/对用户聊天-短答.mdc`](../.cursor/rules/对用户聊天-短答.mdc)；本条为跨 Agent 权威；`AGENTS.md` 仅指针。

## 协作约定

- 高影响未知先询问，低影响问题可采用合理默认并说明假设。
- 事实、观点、推测和未知必须明确区分。
- 长期偏好发生改变时保留变更记录。
