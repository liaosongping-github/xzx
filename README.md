# 廖送平的产品经理工作空间

这是一个以 Markdown 为知识底座、HTML 为低保真原型载体的个人产品工作空间。当前服务于入职业务与系统熟悉期，并支持需求从收集到验收的最小闭环。

## 从这里开始

1. **你每天打开** [我的工作台](工作台/我的工作台.html)（浏览器）；数据过期时先运行 `node 08-自动化/build-workbench.mjs`。
2. **Agent 开工读** [工作台/今日.md](工作台/今日.md)，再读 [agent切换交接文档](06-长期记忆/agent切换交接文档.md)、工作档案与协作偏好；工作空间 Markdown 是跨 Agent 唯一权威源。
3. 待审草案放在 [待确认区](00-待确认区/README.md)；确认后由 Agent 写入正式路径。
4. 未分类、未验证的材料先放入 [原始文件（Raw）](01-原始文件（Raw）/README.md)。与 Agent 的聊天会由本机自动化同步为 Raw，再分流到知识库与长期记忆。
5. 会议结束后使用 [会议纪要模板](07-模板/会议纪要模板.md)，提取行动、决策和待确认问题。
6. 新需求先登记到 [需求池](03-产品工作/需求池.md)，再从 [需求模板](07-模板/需求模板.md) 创建独立文档。
7. 每周使用 [周复盘模板](07-模板/周复盘模板.md) 清理原始资料、校验知识和更新长期记忆。

## 工作区地图

| 区域 | 用途 | 信息状态 |
|---|---|---|
| `工作台/` | 今日权威文本 + 可视化 HTML | 工作事实 / 视图 |
| `00-待确认区/` | 待审草案（日报、知识候选等） | 待确认 |
| `01-原始文件（Raw）` | 未整理的资料、速记、截图、链接和反馈 | 未验证 |
| `02-业务知识库` | 公司、业务、产品、系统、用户和术语 | 需标注验证状态 |
| `03-产品工作` | 需求池、需求、PRD 和原型 | 工作事实 |
| `04-会议与调研` | 会议纪要、访谈和调研 | 来源材料与结论并存 |
| `05-决策记录` | 重要选择、理由和影响 | 已确认决策 |
| `06-长期记忆` | 工作档案、偏好、事实、开放问题与 agent 切换交接 | 分层维护 |
| `07-模板` | 可复制使用的标准模板 | 基础设施 |
| `08-自动化` | Raw 采集、飞书妙记/Agent 聊天同步与自动知识消化 | 本机自动化（与 IDE 无关） |
| `09-提示词` | 可复用提示词；口令见 [README](09-提示词/README.md) | 基础设施 |
| `99-归档` | 已结束、失效或被替代的内容 | 历史记录 |

## 需求生命周期

`待收集 → 待澄清 → 待评估 → 方案中 → 开发中 → 待验收 → 已完成`

任何阶段均可进入 `暂缓` 或 `关闭`。状态变化应同步更新需求池和需求文档；范围、目标或关键规则变化应写入变更记录。

## 文档规范

- 文件夹、文件名、标题和正文使用中文；稳定编号使用 `REQ`、`PRD`、`DEC`、`SYS`、`MTG`。
- 文件名建议使用 `编号-简短主题.md`，避免空格及 `\ / : * ? " < > |`。
- 日期统一使用 `YYYY-MM-DD`，时间使用北京时间。
- YAML 头部使用英文键、中文值；常用键说明见 [模板说明](07-模板/README.md)。
- 事实必须带来源和验证状态；推测不得写成事实。
- 文档使用相对链接，相关需求、PRD、原型与决策保持双向关联。
