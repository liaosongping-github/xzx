# 待确认区

这里存放 **Agent / 自动化已生成、等廖送平确认后再写入正式路径** 的草案。  
**不是** Raw 资料入口（资料入口仍是 `01-原始文件（Raw）/`）。

## 子目录

| 目录 | 用途 | 确认后写入 |
|---|---|---|
| `工作日报/` | 对内 / 对外日报草案 | `03-产品工作/工作日报/` |
| `工作周报/` | 对外口径周报草案 | `03-产品工作/工作周报/` |
| `产品方案/` | 需求澄清后的方案/设计草案 | `03-产品工作/方案/` 等（见草案 `targets`） |
| `知识候选/` | Raw 消化拟落库的知识草案 | `02-业务知识库/`、`06-长期记忆/待确认问题.md` 等 |
| `协作偏好/` | 拟写入协作偏好的草案 | `06-长期记忆/协作偏好.md` |
| `决策/` | 决策记录草案 | `05-决策记录/` |

## 规则

1. 草案 YAML 须含：`type: draft`、`category`、`status: 待确认`、`targets`（拟写入路径）。
2. 廖送平在 [我的工作台](../工作台/我的工作台.html) 点「确认落库」→ 复制口令 → 粘贴到 Cursor 发给 Agent。
3. Agent 收到确认后：写入正式路径 → 更新相关索引 → 将草案移入 `99-归档/待确认区/` 或标为 `status: 已确认`。
4. `04-会议与调研/` 提炼稿可在消化时直接写入；须确认的是拟写入 `02/`、`05/`、`06/`（协作偏好/工作档案/待确认问题）的内容。
5. 历史已落库知识不回溯进本区；自新规则生效起的新消化适用。

## 口令格式

```
确认落库：00-待确认区/知识候选/文件名.md
修改知识候选：文件名，意见：……
驳回知识候选：文件名，原因：……
```
