## 高消耗模式（比「哪个聊天」更重要）

1. **超长同一会话不换新**：历史工具结果反复进上下文（画板、排障最明显）。  
2. **探索型指令**：「全盘扫描」「随便看看有什么」→ 广读文件 / 多 subagent。  
3. **浏览器/截图进模型**：页面 DOM、截图进上下文极贵（8/4 已踩过；Playwright 合图是对的方向，但别让 Agent 每步都「看图解读」）。  
4. **飞书画板/大 JSON**：导出、整板 overwrite、反复试验。  
5. **会话内消化大 Raw**：一次塞进整份逐字稿/长提炼。  
6. **规则过长且每轮全量生效**：协作正确，但 token 成本固定偏高。

## 后续怎么省（按性价比）

**立刻可做**
- 重活（画板、排障、搭系统）**开新会话**；轻问用短会话或 Ask。  
- 指令收窄：给路径/文件名，避免「全盘扫」。  
- 能本地脚本/CLI 完成的，不要让 Agent 多轮试错（尤其画板尺寸、截图合图）。  
- 简单问答用 **Ask**；只有要改文件时再 Agent。  
- 模型：日常整理用更便宜档；复杂推理再上高档（以你套餐 Usage 里贵的模型为准）。

**工作方式**
- Raw 消化：一次只消化 1—2 条；先读索引摘要，再按需打开源文件。  
- 飞书：继续「只登记链接、不拉全文」；需要时再定点拉取。  
- 自动化：日报/周报保持「草案确认」即可，避免同一天多次全量重跑排查。  
- 少开并行 subagent，除非任务真的可拆且值得。

**中期（需改规则时切 Agent 模式）**
- 精简 always-on 规则：开工必读缩成短清单，细节改「按需链接」。  
- 命令事前说明可改成「仅写/删/外网才说明」，减少只读查询的回合税。  
- 消化提示词避免把整份聊天历史当输入。
