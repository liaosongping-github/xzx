# Playwright 全字段截图与 Token 节流方案

## 核心原则

**页面上实际可见的字段，一个不漏读取、一个不漏截图。**

Token 控制不靠减少字段或减少证据，而是把“字段读取、截图拼接、完整性校验”交给浏览器与本地脚本完成，只把最终结构化结果交给模型。

## 截图与字段采集

- 对每个页面先读取全部可见菜单、页签、查询条件、按钮、表头、固定列、操作列、分页和当前可见表单字段。
- 普通长页使用 Playwright `fullPage` 输出单张完整截图。
- 内部滚动容器按纵向自动滚动；宽表按横向自动滚动。每一段保留重叠区，用本地程序裁切、去重并拼成一张全景图。
- 表格必须覆盖从最左固定列到最右操作列的全部可见字段；表单必须覆盖从顶部到最底部的全部可见字段。
- 对虚拟表格，采集“全部表头 + 当前可见记录行 + 分页区”；不逐行滚动数千条记录，因为这不属于字段完整性。
- 写入 Raw 前执行完整性校验：
  - 表头字段集合与各截图文字/DOM 字段集合一致；
  - 横向位置从 `0` 覆盖到最大 `scrollWidth - clientWidth`，无间隔；
  - 纵向位置从 `0` 覆盖到最大 `scrollHeight - clientHeight`，无间隔；
  - 最终合图尺寸、哈希、遮挡区域和字段清单写入 manifest。
- 最终每个页面只保留一张完整合图；临时分片在合图验收后删除。超过单图像素上限时，输出一份分页 PDF 作为单一证据附件。

## Token 控制

- 不把分片截图、整页 DOM、整页文本逐个回传给模型。
- 浏览器直接输出完整字段清单和采集 manifest；模型只接收：
  - 页面名称与菜单路径；
  - 全量可见字段清单；
  - 按钮、页签、状态和记录数；
  - 已验证跳转关系；
  - 采集异常与待确认项。
- 每个模块只进行一次知识提炼；仅当完整性校验失败、页面加载异常或字段变化时追加一次审阅。
- 截图仅在你明确要求预览时返回一张最终合图，不在执行过程中逐张展示。

## 验收

- 每个页面的 Raw 记录均有“完整字段清单”和一张最终全景证据图/PDF。
- 知识页中的字段说明可逐项反向追溯到 Raw manifest。
- 宽表最右操作列、固定列、隐藏在内部滚动区域的字段均已覆盖。
- 不因节约 token 而省略任何实际可见字段。
- 不保存账号、密码、验证码或会话凭据；截图写入前遮挡登录身份区域。

## 默认约定
