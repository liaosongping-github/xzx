## 用户

收件箱是什么？

## 助手

“收件箱”是所有暂时来不及整理、还不知道该放哪里的工作信息的统一入口，相当于工作空间里的临时中转站。

例如：

- 同事随口提出的需求。
- 会议中记下的零散信息。
- 还没读完的公司资料链接。
- 临时想到的产品问题。
- 用户反馈或系统截图。
- 尚未确认的业务术语。
- 需要之后跟进的人和事情。

它的价值是：先快速记录，避免为了考虑“应该放哪里”而丢失信息。

典型流程是：

```text
信息出现 → 放入收件箱 → 定期整理 → 移入正式位置
```

整理时按内容去向处理：

| 收件箱内容 | 整理去向 |
|---|---|
| 业务或产品知识 | `02-业务知识库/` |
| 新需求或用户反馈 | `03-产品工作/需求/` |
| 重要方案结论 | `05-决策记录/` |
| 会议内容 | `04-会议与调研/` |
| 未确认信息 | `06-长期记忆/待确认问题.md` |
| 今日行动 | `今日工作台.md` |
| 无价值或已过期 | 删除或归档 |

建议的使用规则：

- 收件箱只负责“捕获”，不负责长期保存。
- 记录时只需写清内容、来源、日期和下一步。
- 每天下班前或每周固定时间清理。
- 内容原则上不要停留超过 7 天。
- Agent 每次整理时可以提出归类建议，但不确定的信息不能直接写成已验证事实。

最小版本可以只创建一个文件，而不是文件夹：

```text
01-收件箱.md
```

每条内容使用简单格式：

```markdown
## 2026-08-03｜待处理

- [ ] 张经理提到目前退款流程耗时较长
  - 来源：与张经理口头沟通
  - 类型：潜在需求
  - 下一步：确认具体耗时、影响用户和现有流程
```

对刚入职阶段而言，我建议保留收件箱，因为前期会接触大量零散、真假未明且暂时无法分类的信息。等信息量明显增大后，再把单文件升级成文件夹。
