## 推荐切入顺序（你 + 我）

### 1. 先口头同步「这是什么需求」（5–10 分钟）

你尽量用自己的话说明，不必完整：

| 你告诉我的 | 示例 |
|---|---|
| 需求一句话 | 「客户要在销售单上支持某某能力」 |
| 来源 | 谁提的、会议/飞书/口头、有无链接 |
| 产品/模块 | 双引鲸哪一段（销售/采购/仓库…） |
| 期望时间 | 有没有排期压力 |
| 你已掌握 vs 不清楚 | 已知事实 / 猜测 / 完全未知 |

我会按协作偏好做认知矩阵：你知道的沉淀；我从知识库补的标来源与可信度；双方都不知道的进待确认问题。

### 2. 一起做「开工包」核对（再动手写 REQ）

在写正式需求前，我会帮你对照现有沉淀，例如：

- 双引鲸专题与主链路候选知识  
- 待确认问题（含 Q-032—Q-038）  
- 相关 Raw / 会议提炼  
- 你正在写的状态扭转、流程图是否覆盖本需求  

目标：判断是**独立新需求**，还是**熟悉期延伸任务**（例如状态扭转本身还不算正式 REQ）。

### 3. 再落第一份需求文档（状态：待澄清）

结构用 [`07-模板/需求模板.md`](07-模板/需求模板.md)，参考演示需求的关联方式：

`需求 REQ` →（可选）`PRD` →（可选）`决策 DEC` →（可选）`原型`

第一版只求把问题说清，不必一步到位写方案。最低限度写清：

- 背景与来源  
- 当前问题  
- 目标 / 非目标  
- 范围内外  
- 验收标准（可先草稿）  
- 待确认问题列表  

### 4. 高影响未知先问人，低影响可先假设

例如角色权限、字段权威定义、是否改主流程——先问郭强/业务；交互细节等可先标假设再验证。

### 5. 文档写稳后，再进方案 / PRD / 原型

顺序建议：问题与范围对齐 → 方案/决策 → PRD → 原型。避免一上来就画界面。
