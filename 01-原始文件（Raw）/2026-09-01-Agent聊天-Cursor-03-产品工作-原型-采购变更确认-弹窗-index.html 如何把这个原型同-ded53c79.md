## 助手

**不能一键同步。** 这份 `index.html` 是本地 HTML，摹客 Web 吃的是自己的画布；RP **不能**把通用 HTML 变成可二次编辑的组件。

要「进主项目且还能改」，只能在慕客里用原生组件重搭**增量**，HTML 当对照：

- **只回写改动点**：销售/跟单列表操作栏最右加入口；再加「采购变更确认」弹窗（卡片、对照表、同意/拒绝）。侧栏、查询、列表壳主文件已有，整页导入会重复。
- **做法**：浏览器打开该 HTML → 慕客打开主项目对应列表页 → 按画面改组件、补热区。细交互（筛选、Toast）不必 100% 搬，给前端对照本地 HTML 即可。
- **截图可贴，但不能当可编辑控件**；赶评审才贴图。
- **摹客3**才有 HTML 还原（zip 导入后再拷进主文件）；本页还依赖 `shell.css` / `components.css` / `shell.js`，单文件 zip 还原会缺样式。RP 只吃 Axure 包。

数据报表当时就是这条路（手画回写）。你主文件是 **RP 还是摹客3**，回写方式才能钉死。

## 用户

有什么办法可以解决这个问题吗

## 助手

**能解决的是把回写压成「只改增量页」；一键变成可编辑慕客画布，目前做不到。**

推荐你们现在就用这条（摹客仍当权威）：

- Agent 交三样：改动页 HTML、对照清单（哪一页、加了什么、交互）、全页截图。
- 你只在主项目里改对应列表页：加入口按钮 + 新建弹窗画板，侧栏/未改页不动。
- 弹窗用慕客原生组件按 HTML 搭一遍，才能二次编辑、才能跟主文件一起迭代。
- 细交互（筛选、Toast）不必搬，前端对照本地 HTML。

若公司已开通**摹客3**：可把该需求打成 zip 做 HTML 还原，再把生成页拷进主文件——能省搭架子的时间，JS 交互和样式仍要手修。RP 没有这条路。

彻底去掉手回写，只剩两条：换权威源到 HTML，或等慕客开放可写 API。昨天已否决换工具，所以现阶段就按「施工包 + 只回写弹窗」做。

## 助手

**推荐 Framer。** 市面上最接近「Agent 出 HTML → Web 里还能可视化改」的，不是另一款慕客同类。

- 页面底层就是代码，和我出的 HTML/React 同源，能进编辑器再拖、再改、再发布。
- 演示即真页面，列表/弹窗保真度比画布工具更接近现网。
- 代价：不适合「一个文件改全产品」；表格和组件要自己接；国内账号/网络要先试。

若更在意全员在画布上改、当公司权威源，选 **Figma**（国内可看 MasterGo）。HTML 只能插件还原成图层，交互仍要手接，Agent 写不进画布这点只减轻、不消失。

不要换成墨刀/Axure：和慕客同一类问题。换任何画布工具，现有全量慕客都要重做。若核心是和我协作，权威源继续 HTML 比换工具更彻底。
