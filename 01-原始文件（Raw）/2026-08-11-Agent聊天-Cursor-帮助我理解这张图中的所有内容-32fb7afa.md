## 二、左侧流程图（按走向）

### 1. 上游入口（四种来源 → 销售订单）

| 节点 | 含义 |
|---|---|
| 销售报价 | 常规报价 |
| 展厅择样 | 展厅选样单据 |
| 小竹熊选品报价 | F2B/选品侧报价 |
| 站点报价单 | 站点侧报价 |

路径大致是：选品类可先「选品转报价」，再与报价一起进入**销售订单**（也可手工建单，见右侧规则 3）。

### 2. 中枢：销售订单

所有后续「一键采购 / 一键出货计划 / 一键订单出货」都从这里出发。系统按**未完成数量**向下推单，而不是每次全量复制。

### 3. 左支：采购链

```
销售订单 ──一键采购、按厂商拆单──► 按需采购
备货采购 ───────────────────────►（汇入同一采购下游）
        ↓
   采购查货收货
     ├─一键入库──► 采购入库
     └──────────► 采购应付（厂商应付）
```

- **按需采购**：按销售订单里商品、按厂商拆成多张采购。
- **备货采购**：不绑具体销售需求的备货，仍进同一查货/入库/应付。
- **查货收货**：跟单确认到货/验货；入库数量不能超过查货数量。
- **采购入库**：仓存进；**采购应付**：对厂商挂账。

### 4. 右支：出货 / 销售履约链

```
销售订单 ──一键生成出货计划──► 出货计划 / 排柜计划
销售订单 ──一键订单出货─────► 客户出货发货
出货计划 ──────────────────► 客户出货发货
        ↓
   客户出货发货
     ├─一键出库──► 订单出库
     └──────────► 客户应收
```

- **出货计划/排柜**：外贸常见的排柜、计划出货。
- **客户发货**：对客户的实际发货单据。
- **订单出库**：仓库出；**客户应收**：对客户挂账。

### 5. 跨支虚线：查货 → 发货

图中「采购收货—一键出货」表示：货验完后可直接推客户发货（类似直发/越库），不必强行走「先完整入库再出库」的长路径。具体是否总是可用，要以实操/郭强确认为准。

## 三、右侧业务规则（逐条）

| # | 规则要点 |
|---|---|
| **1** | 报价 → 订单：默认带数；生成后**相互独立**，改一边不影响另一边。 |
| **2** | 报价无上下游锁：即使已生成订单，**报价仍可改**。 |
| **3** | 订单可来自报价或手工；**不受报价库存限制**；生成时可提示库存预警（图中红字）。 |
| **3.1–3.5** | 有下游后：**客户信息不可改**；已开始出货则数量改动受限；**厂商信息可改**；已有应收则**价格不可改**。 |
| **4** | 一键采购：按订单商品汇总、**按厂商拆单**；数量取「未采购」；订单改厂商时提示是否同步采购。 |
| **5** | 查货可一键或手工；收货量 ≤ 查货量；数量齐时可提示把订单标「完成」。 |
| **6** | 入库：从查货一键，默认「未入库」数量。 |
| **7** | 应付：从查货生成或手工选；量不超过查货；**一旦生成应付，相关查货信息不可再改**。 |
| **8** | 出货计划：从订单一键，默认该单全部「未出货」。 |
| **9** | 客户发货：从订单一键，默认「未发货」。 |
| **10** | 应收：从发货一键，默认「未开应收」并自动扣减待开数量。 |

### 通用规则（图底）

1. **数据继承**：全链路自动带数；默认取「未完成/待处理」量，也允许手工改。
2. **销转采**：默认未完成项；支持**多张销售订单、同一厂商合并成一张采购**。

## 四、设计上反复出现的三个原则

1. **未完成量驱动**：采购/入库/出货/应收应付都按「还剩多少没做」默认带数，避免重复推满量。  
2. **有下游就锁上游关键字段**：客户、价格、查货信息等，防止账实、单据链断裂。  
3. **一键 = 按规则拆分/汇总**：按厂商拆采购、按未出货推计划/发货，减少重复录入。
